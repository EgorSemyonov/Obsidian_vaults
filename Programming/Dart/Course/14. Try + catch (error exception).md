
## Error/exception
В Dart существует 2 вида ошибок: 
- error
- exception
Данные два вида ошибок никаким образом не взаимосвязаны и не наследуются друг от друга

`Error` - это критический сбой, который возникает из-за проблем в самом коде или из-за некорректной работы виртуальной машины
Примеры:
- `OutOfMemoryError` — закончилась память
- `StackOverflowError` — бесконечная рекурсия (функция вызывает саму себя без конца)
- `NoSuchMethodError` — попытка вызвать метод, которого нет у объекта

`Exception` - это ожидаемые проблемы, который возможно предвидеть и обрабатывать. Возникают из-за некорректных данных или внешних условий
Примеры:
- `FormatException` — строка не может быть преобразована в число
- `TimeoutException` — запрос к серверу занял слишком много времени
- `FileSystemException` — файл не найден

Ошибки `error` лучше исправлять, а не обрабатывать, а вот ошибки `exception` обязательно нужно обрабатывать с помощью конструкции `try catch`

**Итог**:
**Error** — это **"всё сломалось"**, надо чинить код
**Exception** — это **"что-то пошло не так"**, но программу можно спасти

Мы можем эмулировать срабатывание ошибки, используя ключевое слово `throw` и функцию `UnimplementedError()`
```
void main() {
  summarize(40, 2);
}

int summarize(a, b) {
  throw UnimplementedError();
// return a + b;
}
```

## Try/catch

В случае, если мы ожидаем потенциальную ошибку `exception` в логике работы нашей программы, то нам необходимо обработать ее с помощью `try catch`
```
void main() {
  try {
    summarize(40, 2);
  } 
  catch (error) {
    print("Error during the summarizing");
  }
}

int summarize(a, b) {
  throw UnimplementedError();
  // return a + b;
}
```

Еще один наглядный пример, создания логики обработки ошибки (выброса исключения)
```
void main() {
  try {
    devide(40, 0);
  } catch (error) {
    print(error);
  }
}

double devide(int a, int b) {
  if (b == 0) {
    throw Exception("You can't divide by 0");
  }
  print(a / b);
  return a / b;
}
```
Результат: `Exception: You can't divide by 0`

Блоку catch можно указать конкретный тип ошибки, которую он обрабатывает и следовательно, если ошибка будет другого типа, то блок обработки ошибки `catch` не сработает
```
...
on Exception catch (error) {
    print(error);
}
...
```

У конструкции `try catch` существует также такой блок как `finally`, который запуститься в любом случае, не взирая на наличие или отсутствие проблемы
